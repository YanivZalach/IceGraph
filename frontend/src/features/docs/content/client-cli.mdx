`icegraph-client` is a Python client and CLI for the same backend API this UI uses - handy for scripting access to tables, snapshots, and the metadata graph.

### Install

`icegraph-client` is only guaranteed compatible with the exact same version of the IceGraph server it talks to - they're released together. Install that version:

### Point it at your server

Pass `--base-url`, or set it once via the `ICEGRAPH_BASE_URL` environment variable.

If your server sits behind auth, pass `--token` (sent as an `Authorization: Bearer` header) or `--cookie`, or set them via the `ICEGRAPH_TOKEN` / `ICEGRAPH_COOKIE` environment variables.

IceGraph itself doesn't have a login system, so you'll only need a token or cookie if your team has placed the server behind its own proxy. If you're already able to reach the IceGraph UI in a browser, that proxy has already authenticated your session - you can find the value it's using by opening DevTools → Application/Storage → Cookies (or the Network tab → any request → Request Headers) on the IceGraph page. If that doesn't apply, or you're not sure, it's best to check with whoever set up your IceGraph server - they'll know how their proxy handles authentication.

If your server uses a self-signed or otherwise untrusted TLS certificate, pass `--no-verify-ssl` to skip certificate verification, or set the `ICEGRAPH_NO_VERIFY_SSL` environment variable.

### Anonymous user ID

The CLI and Python client send an anonymous ID, saved in `~/.config/icegraph/client_id`, so the server can count its users.

### Commands

```bash
icegraph tables
icegraph snapshots <table> [--before-snapshot-id ID]
icegraph metadata <table>
icegraph sparkdesc <table>
icegraph graph <table> [--start-snapshot-id ID] [--end-snapshot-id ID]
icegraph partition <table> --filter FIELD=VALUE [--filter FIELD=VALUE ...] [--snapshot-id ID]
```

Each command prints its result as JSON on stdout, so it pipes and redirects cleanly (e.g. into `jq`, Python, or a file). Status messages go to stderr, so they never end up mixed into the JSON output.

`snapshots` returns one page of the table's history, starting from its newest snapshots, as `{"snapshots": [...], "next_before_snapshot_id": ...}`. Pass `next_before_snapshot_id` as `--before-snapshot-id` to get the next older page. It is `null` when no older snapshots remain.

`metadata` returns the table's latest metadata, plus `warnings`, which maps a source to a list of messages and is empty when there are none. For example, it warns when the table uses an Iceberg format version other than 1, 2, or 3, which IceGraph doesn't fully support yet.

`sparkdesc` returns Spark's description of any table Spark can resolve, Iceberg or not, as `{"spark_schema": {...}, "spark_partitions": [...], "sections": [...], "properties": {...}, "warnings": {...}}`. Use it when another command reports that the table is not an Iceberg table.

`partition` returns every data and delete file of one partition at one snapshot, with the snapshot and the manifests that point to them, as `{"nodes": [...], "summary": {...}, "issues": {...}}`, the same result as the Partition Files pages. Each `--filter` takes a partition field and its value in the same form as the Partition Files form, such as `ts_hour=2024-03-15-10`; repeat it for more fields. Without `--snapshot-id` it uses the latest snapshot. When the partition has more files than the server's limit, it fails and prints a Spark SQL query that lists every file.
