### 1. Enter the table name

From the Home page, type the fully-qualified name of your Iceberg table (e.g. `database.table_name` ) and press Enter or click Continue. You can also click **Browse catalog** to list Iceberg tables from the Spark catalog. Use the filter field to narrow the list when many tables are available. When the non-Iceberg catalogs are included, the list notes that non-Iceberg tables may also appear.

### 2. Pick a snapshot range

IceGraph shows the table's snapshot history as a single list, newest first. The list starts with the most recent snapshots. Click **Load older snapshots** near the bottom to add the next older batch to the list, as many times as you need. The row disappears once the whole history is listed. Click a snapshot to start a range, then click a second snapshot to finish it. The two ends are ordered automatically, and the range is inclusive. Clicking once more starts a new range. Click **Latest** at the top to end the range at the newest snapshot, or **Full history** at the bottom to start from the table's first snapshot. Full history is not recommended for tables with many snapshots, since it is slow to build and produces a cluttered graph. A smaller range loads faster and produces a less cluttered graph. Click **Generate Graph** or press Enter to continue. A table with no snapshots yet shows a note instead of the list, and you can still generate its graph.

The page also shows the table's latest metadata without building a graph. The metadata file and current snapshot statistics appear above the list, and the schema, partitioning, sort order, technical details, and metadata JSON appear below it. The Schema, Spec, and Order links and the navbar **Specs** button open the Specs panel here as well.

When the table has a `comment` property, its text appears below the table name. The Schema section shows column documentation when recorded and provides a Spark SQL example for adding it.

### 3. Wait for the graph

IceGraph prepares the graph in place of the snapshot list, so the table's latest metadata stays visible around it. The loading panel shows which preparation steps are active and how many have completed, including the final graph build. Large ranges with many data files may take a moment. Once ready, you land on the Timeline view. If preparation fails, the panel shows the error and a button to return to the snapshot list with your range kept.

### Tables IceGraph can't analyze

IceGraph only analyzes Iceberg tables. When the table you entered isn't an Iceberg table, for example a Hive or Parquet table, the snapshot selection page and the Graph view show a single page with the "not an Iceberg table" error at the top. Below the error, IceGraph shows the table's description from Spark's `DESCRIBE FORMATTED` so you can still see what the table is: its Spark schema, its Spark partitions, its table properties, and the detailed table information such as the provider and location. A table that doesn't exist shows Spark's "not found" error instead, without a description.

When Spark can't read an Iceberg table's current metadata file, for example because the file was deleted or moved, the snapshot selection page and the Graph view show a single "Metadata File Unreachable" page. That file is the table's entry point, the metadata file the catalog points to, so the table can't be loaded until the file is restored or the catalog points to a readable metadata file. The page shows the path of that metadata file. Any other error from Spark is shown as Spark reports it. Neither case shows a description, since Spark can't describe a table it can't read.

### Switching tables

While viewing a table, on the snapshot selection page or any table view, click the table name in the navbar to change tables. Enter a new table or use **Browse catalog**, then click Continue. IceGraph opens the new table in a separate browser tab so your current page stays loaded. The navbar **Docs** button and the IceGraph logo, which leads to the Home page, also open in a new tab, so your selected range and loaded graph are kept.
