Shows all data files in your selected snapshot range organized as a directory tree, grouped by their partition paths. Partition paths follow stored field order and show formatted values, such as `event_ts_hour = 2025-06-15 11:00` for fields whose name ends in `_hour`. Unpartitioned files appear under `Root`.

This view solves a common source of confusion: if you look at the **raw storage directory** written by your engine (Spark, for example), you see all files ever written, including files from old snapshots that have since been replaced, and files that belong to different table versions.

**What's on disk is not the same as what Iceberg considers the current table.** The FileTree view shows only the files Iceberg actually tracks as part of the selected snapshots, giving you a true picture of the table's data.

- Expand directories to see individual files
- Focus a file or directory and press Enter or Space to inspect it
- Directories start collapsed, and large trees render only the rows visible in the viewport so expanding many files remains responsive

- Choose a branch, and within it, a snapshot to explore
- Switch between every file in a snapshot and only files added by the selected commit

- Branch, selected snapshot, file scope, grouping, and search are stored in the URL so the current FileTree view can be refreshed or shared

- Select a file, partition, or partition-path step to inspect file counts, sizes, data-row and delete counts, and readable per-column metrics, including null and NaN percentages, average bytes per value, column-size share, and inferred metadata size. Click a metric-table heading to sort by its original value. Click it again to reverse the order, then once more to restore schema order. For a partition or directory, bounds are the smallest and largest across its files; geometry, geography, and variant bounds are not combined

- A file's **Partition** section matches Graph: one row per partition, with full field details on hover, focus, or click.

- **Data rows (before deletes)** counts only records in data files; delete records are shown separately and are not subtracted, because an equality delete can remove many rows or none

- File counts and size totals include data and delete files. Column metrics are shown separately for data, position-delete, and equality-delete files, and describe stored values before deletes are applied

- If the selected snapshot or one of its included files could not be read, an error notice identifies the file and explains why. Several errors or warnings in one notice are separated by divider lines

- If an inspected file has warnings, they appear in a notice at the top of the inspector, separated by divider lines

- If graph data references a missing node, a warning explains that some files may be absent instead of silently showing an incomplete result

- If a readable snapshot has unreadable snapshots in its loaded history, a warning identifies them. Added in commit compares with the nearest readable parent and may therefore span multiple commits

- Many small files in one partition path often indicates a small-file problem

- **Copy paths** copies physical file paths, rather than vector IDs with `#<offset>`. If selected vectors share a Puffin file, its path is copied once

- If the loaded data/delete entry counts disagree with the selected snapshot's summary, a warning shows both counts. Bounded graphs can omit manifests inherited from before the selected graph range. The displayed counts and metrics then describe only loaded files; expand the graph range to include earlier snapshots and check collection warnings

- Deletion vectors are listed one per vector, as `<Puffin file path>#<offset>`, and counted separately from **Position deletes**. They have no column metrics. Totals use the vector's own size, so a shared Puffin file isn't counted twice; the inspector also shows the whole **Puffin file size**. A folder shows its **Deletion vectors** and **Deleted positions (vectors)** counts only when it contains deletion vectors

- On format version 3 tables, each data file shows its `first_row_id`; its rows have IDs from `first_row_id` to `first_row_id` + **Data rows (before deletes)** - 1

- Each file shows its **first appearing timestamp** tracked by Iceberg in the **asked snapshot range**

- Each folder shows a **last modified** timestamp - the most recent first-appearing timestamp among all its files
