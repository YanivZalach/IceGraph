Timeline shows what happened to your table in the selected range, newest first. Each row names the event, shows its impact and time, and includes a short snapshot ID when available.

### Read the list

- **Circle** means the event wrote a snapshot. A **white-filled circle** marks an unpublished write, and a **tick** marks a metadata-only event.
- **+/− chips** count rows added or removed. For compaction, they count files. Row counts may be unavailable when the snapshot expired or is outside the loaded range.
- **Branch chips** identify writes and branch moves on multi-branch tables. A rollback moves the current snapshot to a known ancestor.
- **Branch lanes** draw the history as a tree on multi-branch tables. Each branch gets its own lane from the event that created it to the event that dropped it. A curve marks where a branch forked off, and where main moved to a branch head. An unpublished write sits on the lane it was written from. Hover over a lane, curve, or event marker to see its branch name. Lanes stay unconnected across unreadable events, and the list falls back to a single line while a filter is active.
- **Statistics added**, **removed**, or **updated** marks a metadata-only event that changed the table or partition statistics files, naming the snapshot each file describes.
- **Metadata updated** marks a metadata-only event IceGraph does not recognize. Its row lists the fields that changed, and its details open the **Raw metadata diff** when there is one.

Use **All**, **Writes**, or **Metadata** to filter by event type. When a branch picker is available, use it to see that branch’s writes and ref changes. The event count shows how many rows match.

### Explore an event

Click a row, or focus it and press **Enter** or **Space**. Use **↑** and **↓** to move between events. **Esc** closes the details, and the next arrow key reopens the last selected event. Drag the colored divider to resize the panel, or focus the divider and use the arrow keys; double-click it to reset the size. On a narrow window the panel moves below the list and the divider resizes it vertically.

- **Change summary** shows added and removed rows, files, and data sizes when available. **Table state** shows the before-and-after totals.
- A link such as **View schema 3** opens Specs in Diff mode when it can compare the event’s before-and-after schemas. Use the diff to inspect nested changes within a column. Closing Specs returns to the selected event.
- **Raw metadata diff** shows each changed metadata field as a line diff: **-** lines hold the old values and **+** lines the new ones. Long fields show only the changed lines and their neighbors; select **All N lines** to see the whole field.
- **View in graph** opens the event’s snapshot or metadata file in a new tab with the node selected and locked. A Spark job link appears when the snapshot includes one.

### Understand gaps

**Earlier events not loaded** takes you back to snapshot selection. Events that could not be read appear as one amber row where they belong in the history, including at the very top. Select it to see each file and why it could not be read. These rows are not counted as events and are hidden while a filter is active. The event right after such a row reads **Change unknown**: its change cannot be worked out, so the list claims nothing, marks it as neither a write nor a metadata change, and its details show only the event's own state. Like the unreadable row, it is hidden while a filter is active.

Every metadata file in the range appears as an event. **Start of history** marks the first surviving metadata file when the full history is loaded and that file wrote no snapshot. In a truncated range, the oldest row shows the snapshot it wrote, so the snapshot a range starts from appears as its own event. When the oldest file wrote no snapshot, the event before it is not loaded, so the row reads **Change unknown** like the event after an unreadable row.
