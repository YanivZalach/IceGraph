A git-log-style list of every commit in your selected range, newest first. Each row shows what happened in plain language (**Data added**, **Files compacted**, **Schema changed**, ...), the rows and files it added or removed as +/− chips, the snapshot it produced, and when.

### Reading the rail

The line on the left is the commit rail: a **circle** marks a commit that produced a snapshot (a write), a **tick** marks a metadata-only change (schema, settings, branch and tag bookkeeping).

### Branches

When the range contains branches, every write carries a colored chip naming the branch it landed on — **main** included. A branch merge or fast-forward renders as **main moved to branch** with both names as chips. Single-branch tables stay chip-free.

### Keyboard

**↑** / **↓** move the selection through commits (starting from the newest); **Esc** closes the details panel.

### Details panel

Click a commit (or press **↓**) to open its details in a resizable panel: what this change did (added/removed counts), the table state before and after it, engine info, the metadata file, refs, properties, and a raw metadata diff against the previous commit. Values that matter as ids carry a clipboard icon. Backend read errors and warnings for the commit appear as banners at the top.

When the commit's snapshot points at the job that wrote it, an **`action_link`** row links out to it, opening in a new tab.

The list is honest about its edges: a muted **N earlier commits not loaded** link at the bottom jumps to snapshot selection when the range is truncated, and commits the backend could not read are counted in an amber notice instead of silently disappearing.
