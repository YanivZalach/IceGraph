The Graph view shows all Iceberg metadata objects in your selected range as a directed acyclic graph. Each node is a file, except the Catalog node and deletion vectors, which get one node each even when several share a Puffin file. Links connect node edges, with arrowheads pointing from parent to child.

### Node types

- **Metadata file** - JSON file describing the full state of the table at one point in time: schema, partition spec, properties, and the snapshots it knows of. It links only to the snapshots it points to: its current snapshot and the head of each branch. The other snapshots it lists, kept for time travel until they expire, are not linked; they appear in `pointed_snapshots_files` in its details panel. The statistics files it lists appear in `pointed_table_statistics_files` and `pointed_partition_statistics_files`. Its `format_version` is the Iceberg format version the table had when the file was written

- **Snapshot** - Avro file that represents a point-in-time version of the table produced by a data operation (append, overwrite, etc.)

- **Manifest** - tracks which data files exist and stores per-file statistics

- **Data file** - the actual Parquet, ORC, or Avro file containing your rows. IceGraph is not reading the data file: all of the data shown comes from the manifest entries that point at it. When available, the details panel also shows human-readable per-column metrics derived from the manifest entry, including the inferred metadata size that is not represented by reported column sizes. On format version 3 tables, files written by an update or merge can also show metrics for `_row_id` and `_last_updated_sequence_number`.

- **Position delete** - file listing deleted rows by data file path and row position. `row_count` is the number of deleted positions

- **Equality delete** - file of column values; every row matching one of them is deleted. `row_count` is the number of these values, not the number of rows they delete

- **Deletion vector** - a format version 3 delete: a bitmap of deleted row positions for one data file, stored in a Puffin file. One Puffin file can hold deletion vectors for many data files, so each deletion vector is its own node, with its own partition, row count, and status in each manifest. Its node ID is the Puffin file path followed by `#` and its `content_offset`. `referenced_data_file` is the data file it deletes from, `row_count` is the number of deleted rows, `content_size_in_bytes` is the size of the vector, and `file_size_in_bytes` is the size of the whole Puffin file. A **deletes from** link points from each deletion vector to its `referenced_data_file` when that data file is in the graph, curving out to the right of the column

On format version 3 tables, snapshots, data manifests, and data files show `first_row_id`, where their row IDs start; snapshots also show `added_rows`. If branches gave a manifest or file different row IDs, `first_row_id_by_snapshot` lists each value instead.

- **Table statistics** - Puffin file with column statistics, such as distinct value counts, for one snapshot. Drawn in amber left of the metadata files and linked from the metadata file that added it. IceGraph shows what the metadata file says about it, without opening it

- **Partition statistics** - Parquet file with per-partition counts, such as records, files, and deletes, for one snapshot. Drawn in silver left of the metadata files and linked from the metadata file that added it. IceGraph opens it and shows how the data is spread across partitions, plus a sample of the most recently updated partitions. The distribution caption **Per partition across all partitions** means it covers every partition in the statistics file. The details show `partitions_with_deletes` as a separate count, counting a partition when it has position delete files, equality delete files, or deletion vectors, and treating missing or null counts as zero. Samples use a shared set of fields across the collected statistics files. Sample partitions use the same formatting and per-field details as data files. Only the newest files, up to a configured limit, are opened; older files show only their metadata fields and a warning

- **Catalog** - not a file. It is the entry point to the table: the catalog is what points to the current main metadata file, and every read of the table starts there. It is drawn larger and highlighted, labelled with the table name, and sits at the top of the metadata column, with a downward arrow to the main metadata file. Its details show the table properties that do not change between updates: name, UUID, location and format version

- **Unreadable file** - a file whose metadata could not be obtained is drawn in red and shows the reason in its details panel. The rest of the graph still loads

### Interactions

- Click a node to select it and open its details in the side panel

- Drag a node to reposition it
- Scroll to zoom, drag the background to pan

### Details panel

The panel on the right lists every metadata field for the selected node. The header shows the file type, path, and timestamp; fields below use the same layout as Timeline and other views.

- **Partitions** - one row per complete partition, in stored field order, with `name = formatted_value` segments. Hover, focus, or click a segment for its `name`, raw `value`, and `formatted_value`. Fields whose name ends in `_hour` show their value as an hour labeled `UTC`; other values are shown as stored. The `UTC` label is how IceGraph decodes the stored hour count, not necessarily the source column's timezone: for a `timestamp` column without a timezone, the hour is in whatever local time the writer used. Unpartitioned files show `Root (unpartitioned)`.

- **Virtual read** - data files, position and equality delete files, and table statistics files show this badge at the top of the panel when the backend marks them as virtually read. Hover, focus, or click the label for its explanation: details come from Iceberg metadata. IceGraph does not read this file or verify that it exists.

- **Resize** - drag the grip handle on the left edge of the panel to widen it. Wider panels give text fields more room and show more lines before you need to expand a field.

- **Fullscreen** - click the expand button in the panel header to fill the graph area. Click the compress button or press **Esc** to exit.

- **Copy** - use the button beside the node heading for its complete backend details as JSON, or an individual field's clipboard icon for just that value.

- **Long values** - fields with many lines can be expanded or collapsed individually with **▼** / **▲**.

### Reading the graph

Nodes shared across multiple snapshots mean Iceberg reused those files, data that didn't change is never rewritten. Seeing many shared data files between snapshots is normal and efficient. A snapshot with no shared manifests or data files means a full overwrite occurred.
