The **Specs** button in the navbar, on table pages and on the snapshot selection page, opens the Table Specification panel, which shows the full history of your table's structural definitions across three sections:

- **Schema History** - every schema version the table has had, showing each by its schema ID

- **Partition History** - every partition spec version, showing each by its spec ID

- **Order History** - every sort order version, showing each by its order ID

The Metadata view and the latest metadata on the snapshot selection page can open a definition directly from their Schema, Spec, and Order links. The selected definition opens immediately. Click **×** on the selected definition to return to the history lists without closing the panel.

The currently active version in each section is highlighted with an **ACTIVE** badge. Click any version to expand its full field-level definition.

On format version 3 tables, a schema field can have default values. When both are the same, the field shows `default:`. When they differ, it shows `initial default:`, the value for rows written before the column existed, and `write default:`, the value used when a writer leaves the column out. A change to either default marks the field as changed in the schema diff, which shows the old and new value.

Schema diff markers appear before each field ID:

- `+` means added
- `-` means removed
- `~` means changed
- `↔` means moved to a new position within the same parent
- `·` marks an unchanged parent containing a nested change

Moved fields appear under both parent paths: `←` marks the old location and `→` marks the new location.
Hovering a marker shows its meaning.

Partition and sort diffs use `+`, `-`, and `~` for added, removed, and changed rows. Removed values are struck through.

Multi-argument partition and sort transforms show all source columns and their schema IDs in argument order. The diff includes changes to those source columns; sort fields with different source lists are shown as removed and added. Unknown transform names are displayed as stored.
