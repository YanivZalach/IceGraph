The **Specs** button in the navbar opens the Table Specification panel, which shows the full history of your table's structural definitions across three sections:

- **Schema History** - every schema version the table has had, showing each by its schema ID

- **Partition History** - every partition spec version, showing each by its spec ID

- **Order History** - every sort order version, showing each by its order ID

The Metadata view can open a definition directly from its Schema, Spec, and Order links. The selected definition opens immediately. Use **Clear selection** to return to the history lists without closing the panel.

The currently active version in each section is highlighted with an **ACTIVE** badge. Click any version to expand its full field-level definition. Schema fields render with their types, including nested structs, lists, and maps. A column's `doc` appears under the field, labelled `doc:`. Partition and sort order fields render as tables. List and map members show their ID, structural name, and requiredness. Use the **Full** / **Diff** toggle to compare a version against the one before it. Schema diffs follow Iceberg field IDs through nested structs, lists, and maps, and include changes to identifier field IDs. They show only changed, added, removed, and moved fields, retaining unchanged parent fields only as the path to a nested change.

Schema diff markers appear before each field ID:

- `+` means added
- `-` means removed
- `~` means changed
- `·` marks an unchanged parent containing a nested change

Moved fields appear under both parent paths: `←` marks the old location and `→` marks the new location.
Hovering a marker shows its meaning.

Partition and sort diffs use `+`, `-`, and `~` for added, removed, and changed rows. Removed values are struck through.
