The **Specs** button in the navbar opens the Table Specification panel, which shows the full history of your table's structural definitions across three sections:

- **Schema History** - every schema version the table has had, showing each by its schema ID

- **Partition History** - every partition spec version, showing each by its spec ID

- **Order History** - every sort order version, showing each by its order ID

The Metadata view also opens this same panel directly from its Schema, Spec, and Order links. The selected definition opens immediately; closing the panel returns focus to the link. The wide panel keeps long schema definitions and comparisons readable, with horizontal scrolling when a definition exceeds the available width.

The panel state is kept in the URL, so a link can point at one definition. `specs=open` opens the panel with nothing selected, and `spec_kind=schema|partition|order` together with `spec_id` opens that definition. Add `spec_view=diff` to open the comparison with the preceding version. The panel falls back to Full when the selected definition has no preceding version, while preserving the Diff preference for the next compatible selection. These parameters work on every table page and are carried across tabs, but are cleared when you change table or snapshot range. If a shared link names a definition the loaded metadata does not contain, the panel opens and says so instead of showing an empty selection.

The currently active version in each section is highlighted with an **ACTIVE** badge. Click any version to expand its full field-level definition. Schema fields render with their types (including nested structs, lists, and maps), while partition and sort order fields render as structured tables. List and map members use the same ID, name, and requiredness order as schema fields, with `element`, `key`, and `value` badges marking Iceberg's structural names. Full and Diff use the same table layout, and diff markers sit beside IDs and priorities so those values remain visible. These are the same components the Metadata view uses, so a field looks identical in both places, and every value is shown exactly as Iceberg records it. Use the **Full** / **Diff** toggle to compare a version against the one before it. Schema diffs follow Iceberg field IDs through nested structs, lists, and maps, and include changes to identifier field IDs. They show only changed, added, removed, and moved fields, retaining unchanged parent fields only as the path to a nested change.

Schema diff markers appear before each field ID:

- `+` means added
- `-` means removed
- `~` means changed
- `·` marks an unchanged parent containing a nested change

Moved fields appear under both parent paths: `←` marks the old location and `→` marks the new location.
Hovering a marker shows its meaning.
