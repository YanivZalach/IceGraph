Lists every data and delete file of one partition at one snapshot, together with the manifests that point to them. It reads the full table as it was at that snapshot, not a snapshot range, so nothing is cut off by the range you picked for the Graph.

### Opening it

On the snapshot selection page, the **Partition Files** card has a snapshot picker and one input per partition field from every partition spec the table has used. Fill in one or more fields and choose **Open Partition Files**; it opens on the FileTree tab. Fields you leave empty keep all their values.

- Enter the partition value, the output of the transform: `yyyy` for `year`, `yyyy-MM` for `month`, `yyyy-MM-dd` for `day`, `yyyy-MM-dd-HH` for `hour` (all in UTC), a bucket number for `bucket`, and the truncated or original value for `truncate` and `identity`. Time partitions are shown in the same form in the results
- Only `=` is supported. Several fields are combined with AND
- Partition fields with string, integer, long, date, boolean, or decimal values can be filtered

### How files are found

IceGraph reads the snapshot's manifests the way Spark does for a partition filter: manifests that can't hold the value are skipped, and each remaining file is checked against the filter. Delete files are linked to the data files they apply to. Partition fields are matched by their field ID, so a field renamed in a later spec still matches.

### Undecided files

A file written under a partition spec that doesn't partition by a filtered field can't be excluded by its partition values: its rows may belong to the partition or not. These files are shown as **undecided**, never dropped, so the result is complete. In the Graph tab they have a dashed gray outline; in the FileTree tab they are grouped under their own heading.

### FileTree tab

Lists the matched files. **Group by**, above the list, groups the files by any partition fields that are not part of the filter, in the order you click them; **None** shows one flat list. Search matches file paths and partition values. Select a file or a group to inspect it; a data file lists the delete files that apply to it, and a delete file lists the data files it applies to.

### Graph tab

Shows the same files as a graph, with the snapshot and the manifests that hold them. Delete files link to the data files they apply to with **deletes from** connections. A manifest or manifest list that can't be read is shown with its error, and the rest of the partition still loads. Search, selection, and lineage work as in the Graph view.

### Large partitions

When a partition has more files than the backend limit (`MAX_PARTITION_FILES_TO_COLLECT`, or `MAX_MANIFESTS_TO_COLLECT` for manifests to read), IceGraph doesn't show a partial result. It shows an error with a Spark SQL query you can run in your own Spark session to list every file of the partition from the `files` metadata table at that snapshot.

**Ask AI** answers questions about the partition, with the partition filter and the chips you select as context.

Table, snapshot, filter, group-by, and search are stored in the URL, so a partition view can be refreshed or shared. Select the table name in the top bar to return to the snapshot selection page.
